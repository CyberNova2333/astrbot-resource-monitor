# 一次巡检怎样成为可确认的通知

当某个镜像返回 HTTP 200 时，里面装的依然可能是半截损坏文件、被代理忽略分片头后的整包内容，或者滞后于其他节点的旧清单。插件不会只凭状态码报喜报忧，而是先以当前配置为唯一依据做内容和摘要校验，再把确认后的异常交由告警状态机与持久化队列投递，直至 QQ 官方会话中的管理员亲自查看并确认。

这一路从上游定时触发开始，首先传入本地配置源定义，接着取回线上线路列表、文件清单与分块样本，最终产出持久化状态、发送动作和人工确认回执。难点在于四重结果必须严格拆开：单次请求成功不等于内容正确，探针报红不等于立刻刷群，状态写盘失败不能丢消息且假装成功，向官方接口提交发送也不等于值班人已经收到通知。

## Step 1: 从配置源取得当前检查依据

插件启动或到达巡检节拍时，优先采用本地面板写入的有效配置字典；如果面板未填有效源，再从环境变量指定的部署配置文件加载设置。来源适配器会依据配置选择直接读取本地镜像列表，或请求中心配置入口提取最新启用线路、版本闸门和可选阈值，同时严守不在代码里保存第二份阈值或线路表的约定。

入口配置是整条抑制链的根节点：如果主入口本身无法拉取或内容损坏，插件立刻产出最高级别的入口故障通知，但并不就此收工，而是继续调用可选备用出口或未过期的上一次好配置做辅助探测，把排查线索附在主告警末尾且绝不用旧阈值代为判绿。配置分层与过期降级细则见[配置源、分层与过期降级](../modules/sources-and-degraded.md)。

## Step 2: 并发检查清单、分块轮转与慢周期任务

取得可用线路后，编排器会先把目标交给合理性与公网地址校验：过滤包含内网 IP、凭据或畸形主机名的镜像，拦截启用数骤降一半以上或阈值段突然消失的异常快照（且拒绝将其提升为健康基准），再以最多 4 并发带禁用缓存头拉取各镜像清单。只有跨镜像出现严格多数的一致指纹时，才会将这份清单作为后续抽样的可信基准。

```text
发现配置 ──▶ 公网与合理性检查 ──▶ 4 并发拉清单 ──▶ 多数一致基准
                                                     │
   ┌─────────────────────────────────────────────────┘
   ▼
快轮次: 轮转取分块 (无破缓存头, Range 206 + MD5 + 测速)
慢轮次: 版本 json ─▶ 2 并发整包流式 MD5 核对 + 每天一次 TLS 证书检查
```

接下来，快轮次按确定的三元组游标抽取分块，**故意不加破缓存头**以真实考验 CDN 缓存与分片支持，只有实际校验通过且未超出 64 MiB 安全上限的字节才计入 7 天覆盖率统计；慢轮次则使用独立任务与 2 并发信号量核对热更版本文件、按需流式检验整包大小与散列，以及对 HTTPS 主机使用已校验公网 IP 建立握手核对证书剩余天数（手动群指令触发时强制禁用整包下载）。这些探针的完整分级与连接护栏分别见[十项探针判据、多数共识与分块轮转](../modules/probes-and-rotation.md)和[目标校验、响应上限与命令闸门](../modules/security-and-gates.md)。

## Step 3: 用滑动窗口、抑制树与静音收敛告警

所有探针返回的单轮结果连同未判定标记汇总送入告警状态机：默认在 3 轮滑动窗口内累计 2 次失败才会真正点燃故障状态，并在连续 2 轮成功后产生恢复通知；未判定结果（`unknown=True`）不推进失败计数也不伪造恢复。针对同一问题，首次触发后在重复提醒间隔内保持静默，唯独级别升高（如证书余期从 14 天内进一步跌破 3 天升为 P0）会打破冷却立刻通知。

两条边界保证群内不会沦为刷屏现场：上游节点已触发报警时，受抑制键保护的下游异常虽然继续在状态机记账却不重复刷群；当管理员通过指令开启维护静音时，未发出的首次通知或故障在静音期恢复时产生的恢复事件都会妥善保留，绝不会被静音白白吃掉。完整窗口与抑制设计见[告警抑制窗口、持久化队列与人工确认](../modules/alert-state-and-delivery.md)。

## Step 4: 持久化队列、逐接收者复核与 QQ 官方确认

状态机产出的消息进入框架层后，会先与覆盖率游标和配置快照一起原子写入状态文件；如果本次落盘失败，任务保留在待发队列里等待下轮重存，**绝不先行发出再丢掉现场记录**。开始投递前，循环每轮准备一个目标接收者前，都会再次检查是否已被静音或该故障已恢复——即使第 1 个群发送耗时较长且期间故障已恢复，第 2 个群也不会再收到过期的告警。

面对接入差异，普通群聊发送成功即移除对应接收目标，而 QQ 官方平台则只记入提交回执、不认为任务完结：

| 通知流转阶段 | 运行时可观察行为 |
| --- | --- |
| 平台实例未就绪或缺少主动发消息能力 | 保留在待发队列供后续查看，不声称已投递 |
| QQ 官方主动接口调用未报错 | 对该会话记为 `submitted`，阻止每轮自动轰炸但继续留队 |
| 管理员发送 `/线路 通知` | 展示该会话最早一条未确认条目并绑定查看者与条目 ID，不移除 |
| 同一管理员发送 `/线路 确认` | 校验管理员身份与当前展示绑定，落盘成功后正式移出队列 |
| 机器人在查看与确认之间重启 | 队列从磁盘恢复，原展示绑定失效，需重新查询一次再确认 |
