# 阅读质量审计

这是审计记录，用于检验本指南是否传授了准确、可验证的系统模型，并明确指出尚未实测或容易误判的风险点。

## 读者模拟

| 检查问题 | 从指南得到的答案 |
| --- | --- |
| 主路径走通了什么 | 从 `endpoint` 或 `mirrors` 配置发现开始，并发检查清单与多数共识，按轮转游标检验分块 MD5 与慢周期版本/证书，经滑动窗口、两级抑制与静音收敛后写盘队列，最后逐接收者复核并完成 QQ 官方查看确认 |
| 整套机制最难的点在哪里 | 四种结果不能混为一谈：HTTP 200 不等于分块或 Range 正确，探针红灯不代表单轮立即刷群，状态写盘失败不能先发再丢状态，官方接口提交不等于管理员确认收到 |
| 各阶段之间靠什么衔接 | 上游入口失败通过 `KEY_ENTRY` 和 `manifest_key` 抑制键屏蔽下游连带告警；轮转游标与 `AlertState` 持久化到同一 JSON 文件；多群发送前通过 `_discard_stale` 对每个接收者实时核对最新状态 |
| 在哪里会拒绝或中止假定 | 超过 `64 MiB` 的缓冲块与缺少多数共识的清单会被标成 `unknown=True` 不计入覆盖；非公网 IP 与重定向内网跳在连接层被拦截；配置突降或异常快照绝不晋升为健康基准 |
| 应该改哪里、跑什么测试 | 可先按职责表从 [代码地图](../code-map.md) 定位到具体模块及对应 `tests/test_*.py`，在仓库根目录执行 `python3 -m unittest discover -s tests -t . -v` 与 `tools/check-no-endpoints.py` |
| 哪些结论仍缺真实环境验证 | 系统缺少 `aiohttp` 导致 5 项 `AiohttpBoundaryTest` 在本地跳过；此外真实 AstrBot 宿主、公网镜像链路及 QQ 官方平台限频送达均未在此环境实测 |

## 可证伪性与后续问题

证伪检查：如果在源码中观察到 `unknown=True` 结果被记为覆盖或计入失败窗口、手动 `/线路 测` 触发了整包流式核对、官方主动发送无异常后直接删除待发队列，或者 `endpoint` 失效时用过期快照判定线路正常，则本指南的对应核心模型必须推翻重写。

读者下一问：日常使用和首次配置部署该看哪些参数与命令？面向插件安装者与管理员的参数全表、环境变量优先顺序与部署常见排错，已完整整理在独立用户文档站 `docs-site/`（含部署配置、探针契约与迁移决策三阶段）。

## 剩余风险

- **运行时依赖与环境差异**：本地开发机系统 `python3` 未预装 `aiohttp`，真实底层连接超时、`TCPConnector` 与 `PublicResolver` 交互需在已安装 `requirements.txt` 的 AstrBot 宿主机或虚拟环境复跑完整 252 项单测后再上生产。
- **示例键名历史差异**：`config.example.json` 样例中保留了 `fire_after` 与 `recover_after` 字段写法，而当前运行时 `watch/config.py` 与 `_conf_schema.json` 均读取 `fire_after_failures`、`fire_window` 与 `recover_after_successes`；已在文档站与配置源模块中显式提示，避免读者照抄旧键失效。
- **真机与平台额度限制**：`QQ_OFFICIAL_PLATFORMS` 主动消息配额、多端并发表现以及外部真实镜像限流均无法在离线替身下完全等价模拟，必须在部署后的试运行会话中用 `/线路 状态`、`/线路 通知` 与 `/线路 确认` 实测验收。
