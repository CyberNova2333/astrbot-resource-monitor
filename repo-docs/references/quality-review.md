# 阅读质量审计

这是审计记录，用于检查指南是否传达了可操作的理解，以及还剩哪些风险。

## 读者模拟

| 检查问题 | 从指南得到的答案 |
| --- | --- |
| 主路径是什么 | 一轮配置发现和内容检查到 QQ 官方通知查询与确认 |
| 难点是什么 | 判定、持久化、平台提交和人工确认是四个不同结果 |
| 阶段如何衔接 | 发现配置 → 内容检查 → 推进告警 → 保存队列 → 平台提交 → 查看确认 |
| 失败和边界在哪里 | 只读监控、无自动修复；离线替身不证明真实 QQ 送达 |
| 如何验证理解 | 主流程末尾给出已有测试或检查入口；本轮未执行业务测试 |
| 从哪里改 | 代码地图逐项给出范围内目录、重要代码和验证位置 |

## 可证伪性与后续问题

证伪检查：若官方发送后直接清除队列、跨用户确认通知，或第一个接收者等待期间恢复后仍向第二个发送过期故障，这份通知模型就失效。应对照投递与官方确认回归逐项核对。

读者下一问：某类 Range 或热更内容具体怎样判失败？从原有 `docs/PROBES.md` 与 `watch/probes.py`、对应探针测试继续；本页不覆盖所有判据。

## 剩余风险

不逐项覆盖所有探针算法、慢周期整包下载和每个平台适配器；没有真实 AstrBot/QQ 交互或云端线路验收，不提供自动修复或内网监控。 文档结构验证和静态站点构建不能替代运行时、平台接线或生产验证；SOURCE 链接需在克隆/代码托管视图使用。README 原有丰富说明保留，root AGENTS 统一规则，CLAUDE 仅作路由。
