监控资源线路时，先按当前线上配置检查内容与摘要，再将确认的故障和恢复放入持久化通知队列。QQ 官方适配器的提交回执只表示尝试提交，通知要由查看者明确确认。

本指南采用 Lite 包加代码地图，聚焦 **一轮配置发现和内容检查到 QQ 官方通知查询与确认**。不逐项覆盖所有探针算法、慢周期整包下载和每个平台适配器；没有真实 AstrBot/QQ 交互或云端线路验收，不提供自动修复或内网监控。

## 运行与验证

部署在 AstrBot 的插件目录，完整保留 `main.py` 和 `watch/`。运行依赖要求 Python 3.10+，按 `requirements.txt` 安装；实际地址和会话只保存在部署侧。离线检查入口为：

```sh
python -m unittest discover -s tests -t .
python tools/check-no-endpoints.py
```

测试使用假 HTTP 和框架替身；安装依赖后连接层测试仍不访问真实线路。部署后的 `/线路 状态`、`/线路 通知` 和 `/线路 确认` 另行验证，不能由本地文档构建替代。

这里给出的业务命令来自现有源码或脚本；本轮只执行文档结构校验与站点构建，没有运行业务测试、安装钩子、停止服务或部署。测试文件的存在表示可检查的验证意图，不表示本轮通过。

## 文档站

文档站采用 VitePress 默认主题，依赖与业务项目分开安装。默认输出 `docs-site/.vitepress/dist/`；独立核验可在构建命令后加 `-- --outDir <仓库外绝对目录>`。指南正文只维护 `repo-docs/`，站点通过 include 读取；网页中的仓库源码链接显示为精确文件路径，不复制源码或本机资源。

```sh
pnpm --dir docs-site install --frozen-lockfile
pnpm --dir docs-site run docs:dev -- --host 127.0.0.1
pnpm --dir docs-site run docs:build
```

独立网页构建会把文档目录之外的仓库链接显示为精确文件路径，避免产生失效跳转；原始 Markdown 仍保留可核对的源码链接。站点只发布指南，源码和本机资源不会随文档打包。
